# 等价性验证报告：hcu-sglang-plugin 与原生 sglang-das

> **本文用途**：记录 hcu-sglang-plugin（A = 官方 sglang 0.5.22 + 插件）与原生 sglang-das（B = fork）在真实模型上的逻辑、数值与性能一致性验证结果、结论边界和未验证项。用于交付验收与交接，不代替 [交付验证记录](delivery-validation.md) 与 [迁移记录](hcu-sglang-development.md)。

## 0. 总体结论

- **47（gfx936 / BF16 KV / Qwen3.6-27B-INT8-w8a8）**：精度**等价成立**（逐层张量逐位相同 + 确定性请求文本 8/8 逐字一致）；性能**未观测到可分辨差异**，不给差异上界。
- **26（gfx938 / fp8_e4m3 KV / TP2，目标环境）**：精度**等价成立**（A 自证 8/8、A/B 8/8、逐层张量 45/45 逐位相同）；**性能未验证**（用户要求停止采集）。
- 两机结论**各自独立成立，互不顶替、不跨机外推**。26 的绝对输出与 47 不同（例如 r02 为 99 字符 vs 101），属机器与 KV dtype 差异。
- **精度结论的前提是相同批组成**：批组成会改变 greedy 输出，两侧表现一致，属既有行为，不构成 A/B 差异。

## 1. 验证范围与方法

| 维度 | 值 |
|---|---|
| A 侧 | 官方 sglang 0.5.22（`baa9befa38`）+ 插件，源码模式 `PYTHONPATH` + `SGLANG_PLUGINS=hcu` |
| B 侧 | 原生 sglang-das `v0.5.22.plugin`（`15c7204b7a`），`SGLANG_PLUGINS=__no_general_plugins__` |
| 容器 | `yangyn_sglang_plugin_1022`，Python 3.10.12，torch 2.11.0 |
| 两侧同参 | `--attention-backend fa3 --page-size 64 --disable-cuda-graph --context-length 8192`，TP2 |
| 节点 47 | gfx936，每卡 65520 MiB，BF16 KV |
| 节点 26 | gfx938，每卡 147440 MiB，fp8_e4m3 KV（目标环境） |

判定口径：精度以**逐位相同**为主判据（`max_abs = 0`），文本以**逐字一致**为主判据；性能以多轮独立启动的中位数差与同侧极差报告，先报噪声地板再判定，不设固定百分比门槛。所有比对脚本先做负例自测，插桩轮先自证不改数值。

## 2. 精度（47 / gfx936 / BF16 KV / 27B）

- **根因与修复**：A 走官方 Triton `l2norm`，B 走 DAS 新增的 `sgl_kernel.l2norm` vendor 快车道，插件此前未迁 `fla/l2norm.py`。迁入后（5 个 REPLACE 目标：`l2norm.l2norm_fwd/l2norm/l2_norm`、`chunk.l2norm_fwd`、`kda.l2norm_fwd`），A/B 从 layer 0 到 layer 63 **逐层 `max_abs = 0.000e+00`**（采样层 0/1/4/8/16/32/48/63，|1081 键）。
- **确定性**：A 侧两次独立启动逐位相同；B 侧三次启动逐位相同（0.6B 对照）。旧基线在 l2norm 迁入前采集，已作废。
- **端到端文本**：此前分叉的 r02、r08 在新代码下 **8/8 请求逐字一致**。
- **权重**：layer 0 的 16 个参数（含 `in_proj_qkvz` int8 与 scale）两侧逐字节相同（`differing 0/16`）。
- **注意力元数据**：6 字段 × 32 记录 compared=192、diff=0。
- **结论**：该配方 + 固定批形状下等价性成立，不外推至 26。

## 3. 精度（26 / gfx938 / fp8_e4m3 KV / TP2 —— 目标环境）

- **文本等价**：A 两次独立启动 A1 vs A2 **8/8 逐字一致**；A vs B **8/8 逐字一致**（按 text + prompt_tokens + completion_tokens 校验）。r02 为 54 token / 99 字符，r08 为 225 token / 430 字符。
- **逐层张量**：采样层 0/1/4/8/16/32/48/63 × 3 个 token 行（`|1`、`|80`、`|1081`），两侧 `tensors.pt` **45 个键全部相等**（`torch.equal` 全等，mismatched 0），dtype / shape / stride 全同。
- **批形状（同一条判据的第二次验证）**：26 上同一 r02 串行 54 token、8 并发 42 token；47 为串行 54 / 并发 33。两机都是“批形状改变输出、A/B 同 sha”，不是跨机差异，也不构成 A/B 差异。
- **工具缺陷（不影响张量结论）**：26 上 `layer.json` 的逐层 sha 与 `fa.json` 的 KV 页哈希存在“首调用捕获”问题——B 的 `layer.json` 每层 sha 恰等于该层张量第 3 行（token 1081），A 的每层 sha 与它自己保存的任何一行都不相等；FA 页 1/2 不同但 layer_4 及之后逐位相同（若真不同不可能相同）。**这两份哈希快照不得用于 A/B 比对，逐层等价证据以 `tensors.pt` 为准。**
- **历史遗留**：26 上曾出现 A 侧一次 699 vs 710 的分叉，发生在拥挤窗口（util 90–100%），**不可采信、原因未定位**；本次干净窗口未复现。

## 4. 性能（47，卡 0/1 独占，A/B 各 3 次独立启动 × 5 个有效轮，8 并发）

| 指标 | A 中位 [3 次启动范围] | B 中位 [3 次启动范围] | 中位数差 | 同侧极差 A / B (pp) |
|---|---|---|---|---|
| output tok/s | 14.804 [14.757..14.863] | 14.942 [14.700..15.144] | -0.93% | 0.72 / 2.97 |
| req/s | 0.3403 [0.3392..0.3417] | 0.3435 [0.3379..0.3481] | -0.93% | 0.72 / 2.97 |
| TTFT p50 (ms) | 464.56 [459.21..468.22] | 462.80 [454.16..471.76] | +0.38% | 1.94 / 3.80 |
| TTFT p99 (ms) | 469.51 [468.24..470.68] | 464.32 [455.48..473.30] | +1.12% | 0.52 / 3.84 |
| TPOT p50 (ms) | 119.01 [117.63..119.79] | 117.32 [115.63..119.94] | +1.44% | 1.81 / 3.67 |
| TPOT p99 (ms) | 153.88 [153.25..156.29] | 154.53 [151.48..159.67] | -0.42% | 1.97 / 5.30 |
| E2E p50 (ms) | 3291.9 [3284.4..3373.3] | 3288.0 [3233.5..3358.7] | +0.12% | 2.70 / 3.81 |
| E2E p99 (ms) | 22309.1 [22211.4..22379.9] | 22099.4 [21799.2..22458.8] | +0.95% | 0.76 / 2.98 |

**判定**

- 8 项中位数差全部落在 **−0.93% ~ +1.44%**。按各指标优劣方向（吞吐越高越好、延迟越低越好）逐项判定：**B 在 7 项上数值略优**（output tok/s、req/s、TTFT p50、TTFT p99、TPOT p50、E2E p50、E2E p99），**A 仅 TPOT p99 一项略优（0.42%）**。
- 同侧 3 次启动之间极差：**A 0.52–2.70 pp / B 2.97–5.30 pp**（最大 5.30pp 为 B 侧 TPOT p99）。波动范围大于中位数差。
- 因此结论为 **“未观测到可分辨差异”**：不得表述为“性能等价”，不得给出差异上界，也不得表述为“A 略优”或“A 更快”。
- **采集规则在跑之前固定**，写进每份结果的 `rules` 字段、跑完未改动：G1 每轮 8 并发中 r02 不得单独入批（禁止 `#new-seq: 1, #new-token: 23`），违反则该轮作废重跑；G2 每轮 8 条 `completion_tokens` 必须等于参考集 `{r01 4, r02 33, r03 18, r04 6, r05 4, r06 32, r07 51, r08 200}`。实测有效轮 30 / 无效轮 7，无效轮指标作废但原始尝试全部保留。
- **旧口径作废说明**：早期一轮给出“中位数差最大 0.83%、极差 4.76%”，其 4.76% 含**工作量差异**（同为 8 并发时有两轮 r02 生成 54 token，其余轮为 33），并非纯计时噪声，已由 `server.log` 的 `Prefill batch` 定性为 r02 单独入批；该组数据与旧判据（≤3% pass / 3–10% warn / >10% fail）均已废弃，保留仅为追溯。
- **观察但未定性**：B 侧 8 项极差全部大于 A（约 1.5–7.5 倍，方向一致 8/8）。判定“B 稳定性更差”需要更多轮次或直接证据，暂不作结论。

## 5. 性能（26）—— 未验证

- 用户要求停止采集，门禁版六次独立启动**未启动**；仅有一轮标定，**不作性能结论、不进对比表**。
- 26 的 8 并发 token 参考集与 47 不同且稳定 5/5：`{r01 4, r02 42, r03 18, r04 6, r05 4, r06 32, r07 51, r08 208}`。若要补测 26 性能，工作量校验必须换成这一组。

## 6. 已知边界与不透明点

1. **结论仅在已验证配方内成立**：27B / Qwen3.5 / fa3 / 无 CUDA graph / 源码模式；47 与 26 各自独立成立。
2. **插件不是透明替换**：0.6B 上 A、B 都走同一 fallback rotary 分支，A 的 kernel 被 dtype 适配包装（调用前把 fp32 `cos_sin_cache` 转成 `query.dtype`），B 无此包装，触发 `RuntimeError: expected scalar type BFloat16 but found Float`。**0.6B 验证路径因此不可用**，且不修改 fork 源码。该差异有 CPU 单测固定，但未做运行期分支命中取证。
3. **KV 布局一致性未验证**：早前用于证明“KV 布局一致”的哈希只覆盖了全零区，属空哈希，该结论已撤回。
4. **hook 对账未闭合**：静态 421 / 运行时 632 / static_only 74 / runtime_only 285 / unexplained 74。
5. **尾延迟**：仅在卡独占窗口下报告；此前跨轮合并分位数得到的尾延迟差异已判定为工具缺陷，不采信。
6. **批组成决定文本**：文本比较必须在相同批组成下进行，仅“并发数相同”不构成可比条件。遗留 1 例同批仍出不同长度的反例（n=1），未解释、未外推。

## 9. 复现要点

1. 在容器 Python 3.10 内执行所有脚本（宿主默认 Python 版本过低会以导入错误形式假失败）。
2. 先做 A 侧两次独立启动自证，确认栈本身可复现，再做 A/B 比对。
3. 逐层 dump 的比对以 `tensors.pt` 为准，不以 `layer.json`/`fa.json` 的 sha 为准。
4. 性能轮：规则固定后再跑；每轮校验批组成与工作量；无效轮记录后重跑，不删除、不挑轮次。
5. 分位数每轮独立计算后取轮次中位数，禁止跨轮合并。
